# Code of Conduct

## The short version

Be decent. Assume good faith. Disagree about the work, not about the person.

## Scope

This applies to issues, pull requests, discussions, and any other space where
someone is representing the project.

## What is expected

- **Engage with the argument.** "This breaks X because Y" is useful. "This is
  bad" is not, and neither is "you clearly don't understand Z".
- **Accept that review is about the code.** A change being rejected is not a
  judgement about the person who wrote it.
- **Take the extra minute.** A terse review comment reads harsher than it was
  meant to, and most people are not writing in their first language.
- **Say when you were wrong.** It costs nothing and it makes the project easier
  to contribute to.

## What is not

Harassment, personal attacks, discriminatory language, sustained disruption,
publishing someone's private information, or unwelcome attention. Deciding that
somebody's question was too basic to deserve an answer counts too.

## Reporting

Email **bagombekajob@gmail.com**. Reports go to the maintainer, who will read
them and respond. If the report concerns the maintainer, say so — and know that
this is a single-maintainer project, so there is no independent body to escalate
to. That limitation is real and it is better stated than discovered.

Reports are handled privately. What happens next depends on what happened:
usually a conversation, sometimes an edit or a lock, occasionally a ban.
