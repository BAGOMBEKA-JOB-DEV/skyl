# ADR-0004: Model IDs are opaque pass-through strings

**Status:** Accepted · **Date:** 2026-08-02

## Context

The brief asked for skyl to support "almost all models". The obvious reading is
a curated list — constants, an enum, validation against a table.

Model releases in a single four-week window in mid-2026:

| Model | Released |
|---|---|
| GPT-5.6 Sol | 9 Jul 2026 |
| Gemini 3.6 Flash | 21 Jul 2026 |
| Claude Opus 5 | 24 Jul 2026 |
| Qwen3.7 Flash | 27 Jul 2026 |

Any table written today is incomplete within weeks. Worse, a library that
*validates* against a stale table actively blocks its users from a model they
are paying for, and the only fix is a skyl release. The library becomes the
bottleneck on someone else's roadmap.

## Decision

`Request.Model` is an opaque `string`, passed to the provider untouched. skyl
**never** validates it against a known list, and ships **no** model-name
constants.

"Almost all models" is delivered by four mechanisms instead:

1. **Pass-through IDs** — models released after your skyl build work
   immediately, with no release.
2. **Live discovery** — `Models(ctx)` queries the provider's real endpoint.
3. **A generated registry** (M6) for metadata — context window, pricing,
   modality — regenerated by scheduled CI from live provider endpoints.
   Generated, never hand-typed, so it cannot silently rot.
4. **The OpenAI-compatible adapter** — one adapter reaches ~18 hosts, including
   OpenRouter's 300+ models, with no per-vendor code.

## Consequences

**Good.** Zero-day support for every new model, permanently. skyl can never be
the reason a user can't reach a model. No stale table to maintain, and no
release pressure when a vendor ships.

**Bad.** A typo in a model ID surfaces as a provider 404 rather than a compile
error. We accept this: the alternative trades a rare, immediately-obvious
mistake for a systemic, recurring one. The provider's error is also more
accurate than ours could be — it knows what that account is entitled to; we
don't.

Editor autocomplete on model names is lost. Live discovery is the replacement,
and it is correct where autocomplete would be merely convenient.

## Alternatives considered

- **Typed constants (`skyl.ClaudeOpus5`).** Nice ergonomics, guaranteed
  staleness, and a release cadence coupled to every vendor's. Rejected.
- **Validate but allow an override flag.** All of the maintenance, most of the
  friction, and users learn to set the flag permanently anyway.
- **Ship a table but only warn.** A warning nobody reads is not a feature; the
  maintenance burden is identical.
